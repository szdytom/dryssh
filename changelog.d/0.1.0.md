# DrySSH 0.1.0

First public preview of a terminal-first Android SSH client, optimized for an
external keyboard. Requires Android 11 (API 30) or later. Download the APK for
your device: `dryssh-0.1.0-arm64-v8a.apk` for phones and tablets,
`dryssh-0.1.0-x86_64.apk` for emulators. Each APK includes only its own native
libraries.

## Features

- Password and private-key authentication, including encrypted keys; host-key
  verification before authentication.
- Saved connection profiles and Android Keystore encrypted credentials.
- One active session, configurable reconnect and strict WLAN-only networking.
- Local IME composition, multiline editor and negotiated bracketed paste.
- Configurable shortcuts, font import, 179 bundled themes and adaptive layouts.
- Local selection/history, clipboard actions and foreground-session controls.

## Compatibility and limits

The maintainer reports that basic functionality passes on an ARM64 physical
device. Automated emulator acceptance covers SSH, input, terminal workflows,
network policy and background/lock survival. See `docs/progress.md` in the source
archive for the detailed evidence and limits.

Reconnection opens a fresh shell. OS process termination loses the active session
and editor draft. Configuration backup/export, jump hosts, Mosh and multiple active
sessions are outside this version's scope.

## Installation and verification

Download the APK matching your device architecture and `SHA256SUMS` from the same
release. Check the download with `sha256sum --check --ignore-missing SHA256SUMS`,
then install with `adb install -r dryssh-0.1.0-arm64-v8a.apk` (or the `x86_64`
file) or Android's package installer. The ZIP includes both APKs and third-party
notices. `SIGNING-CERTIFICATE.txt` records both APKs' certificate SHA-256 digest;
`apksigner verify --print-certs <apk>` should match it. Keep that fingerprint to
check future releases.

Earlier personal development APKs used a different debug certificate and cannot
be updated by this release. Uninstalling clears saved credentials and profiles;
record connection details and retain original private keys before switching.
Future official releases will use the dedicated release identity and an increased
Android `versionCode`.
